## 향후 아이디어: Multi-step Lookahead MPC

### 현재 문제
- Greedy 1-step MPC: 1스텝 앞만 보고 결정
- "이번 스텝은 좋아보이지만 다음 스텝에서 사람이 사라지는" 경우를 예방 못함

### 제안: 2~3 step 합성 lookahead
- 현재: 720 candidates → score → best 1개 선택
- 제안:
  1. 720개 1-step candidates 스코어링
  2. Top-K (30개) candidates의 결과 포즈 계산
  3. 각 결과 포즈에서 follow-up candidates 50개 생성
  4. 2개 action을 기하학적으로 합성 → net displacement + final orientation
  5. 합성된 단일 action text를 현재 이미지와 함께 모델에 넣어 스코어링
  6. 최적 2-step 경로의 첫 번째 action만 실행 (receding horizon)

### 왜 가능한가
- orientation_6d는 target orientation (절대값)이므로 합성이 자연스러움
- 모델은 "현재 이미지 + 이만큼 이동하면 scores가 뭘까"를 예측
- 큰 이동도 학습 데이터 분포 내 (camera_radius_range: 0.5~6m)
- 계산량: 720 + 30×50 = 2,220 model calls per step → vLLM으로 충분

### 기대 효과
- Greedy가 빠지는 local optima 회피
- "1-step은 좋지만 2-step 후 사람 사라지는" 경로를 사전 차단
- 실질적으로 receding horizon MPC와 동일

### 구현 (완료)
- `src/vlm_qwen25/mpc.py`에 `score_with_lookahead_vllm()` 함수 추가
- `scripts/infer_mpc_blender.py`에 `--lookahead_top_k` 플래그 추가 (0=비활성, 30 권장)
- `scripts/run_e2e_mpc.sh`에 `--lookahead_top_k 30` 기본 적용

### 구현 상세
- Top-K(30) first-step candidates에서 각각 follow-up candidates 생성
- 2-step을 기하학적으로 합성:
  - `relative_translation_camera_local()`: current → final 위치를 현재 카메라 로컬로
  - `target_orientation_forward_up_camera_local()`: final orientation을 현재 카메라 로컬로
  - `build_action_text()`: 합성된 단일 action text 생성
- 합성된 전체를 한 번에 vLLM으로 스코어링
- 재랭킹: `objective = 0.5 * 1step_error + 0.5 * lookahead_error`
- 계산량: 720 (1-step) + ~1500 (lookahead) = ~2200 model calls per step

## 근본적 문제 분석 (v1, v3 실험 결과 기반)

### 문제 1: inference step size가 학습 분포 대비 너무 작음 (수정: 모델 문제 아님)
- 학습 데이터: distance_threshold=1.5m, pair 거리 중간값 1.13m (75%가 0.87~1.33m)
- 추론 스텝: max 0.3m (adaptive 시 0.09~0.3m) → 학습 분포의 20% 수준만 사용
- 모델은 1.0m+ 이동도 예측 가능하게 학습됐지만, inference에서 0.2m씩만 움직임
- 결과: occupancy 0.16→0.4 도달에 35+ steps 소요 (0.2m × 35 = 7m 이동)
- Step 10 (4.5m): 720개 candidate 전부 occ≈0.16 (0.2m로는 큰 변화 불가)
- Step 35 (3.3m): occ≈0.39로 수렴
- 해결: translation_values를 0.5m, max_translation_norm을 0.8~1.0m으로 확대하면
  학습 분포에 맞으면서도 수렴 속도 크게 향상 기대

### 문제 1.5: Occupancy 함정 — 잘림과 부족을 구분 못함
- occupancy = bbox(보이는 부분만) 면적 / 이미지 면적 (render_object_v3.py mask 기반)
- 사람이 잘리면 bbox가 작아져서 occupancy가 줄어듦
- MPC 악순환:
  1. occupancy=0.4 target → 카메라가 가까이 접근
  2. 사람이 프레임에서 잘리기 시작 → occupancy 감소
  3. 모델: "occupancy < target이니까 더 가까이 가야 해" → 더 잘림 → 악화
- occupancy만으로는 "적당한 크기로 잘 보이는 상태"와 "너무 가까워서 잘린 상태"를 구분 불가
  (둘 다 occupancy < target)
- 해결 방향:
  - margin 하한 필터 (이미 적용됨, MIN_MARGIN=0.03)를 더 보수적으로 (0.05~0.1)
  - visibility_ratio (mask 픽셀 기반 가시성) 또는 truncation score를 추가 target으로 사용
  - 또는 occupancy 계산 시 잘린 부분을 보정하는 "full-body occupancy" 추정 로직

### 문제 2: 카메라 아래로 drift (MPC greedy 특성)
- 매 스텝 아래로 약간 이동이 단기 error를 줄임 → MPC가 선택
- 50 스텝 누적 → target은 eye-level인데 최종 결과는 low-angle
- 초기 frame: 발 근처 / frame 35: 몸통 정면 (최적) / frame 50: 아래에서 올려다봄
- Greedy MPC의 본질적 문제: 장기적으로 나쁜 방향도 단기 이득이 있으면 선택

### 문제 3: 어려운 target은 수렴 불가
- left hero (fx=0.7, fz=0.7): 현재 위치에서 목표까지 큰 각도 이동 필요
- 모델이 큰 변화를 예측 못하니 방황 → error 0.35→0.44로 악화
- Safety guards가 catastrophic failure는 방지하지만 수렴은 못 시킴

### Safety guards 효과 (v1 vs v3)
- v1 front eye-level: error 스파이크 0.30 반복 발생
- v3 front eye-level: 스파이크 완전 제거, 0.10~0.13 범위 안정
- Safety guards는 성공적. 근본적 수렴 문제는 별개.

## 해결 방향

### 단기 (코드 수정)
1. **Coarse-to-fine 2-phase**: 규칙 기반으로 대략적 위치 먼저 잡기 (거리, 방향) → VLM MPC로 정밀 조정
2. **더 큰 step size 허용**: translation_values에 0.4~0.5m 포함 (멀 때만)
3. **Drift 방지**: 특정 축(z) 이동에 penalty 추가, 또는 target fz=0이면 z축 이동 억제

### 단기 (target generation 개선)
4. **generate_target.py에서 불가능한 조합 방지**: LLM이 occupancy=0.6 + aspect_ratio=0.7 같은 프레임에 안 맞는 조합을 생성할 수 있음. `compile_score_targets()`에서 ValueError로 잡히긴 하지만, 생성 단계에서 validate_target()에 frame fit 체크 추가 필요. 또는 system prompt에 "occupancy × aspect_ratio 조합이 frame aspect ratio (4:3) 안에 들어가야 함" 제약 명시.
5. **c2o orthogonality와 의미적 일관성**: 하이앵글(fz<0)에서 orthogonality 제약 때문에 uz<0 (카메라 뒤집힘) 생성되는 케이스 있음. system prompt 예시 자체가 orthogonality를 완벽히 만족하지 않는 경우도 있어서 LLM이 혼동.

### 중기 (학습 개선)
1. **distance_threshold 확대**: 1.5m → 3~4m pair 포함해서 큰 변화도 학습
2. **더 큰 displacement pair**: 학습 시 max_pairs_per_image 늘리고 먼 pair 포함
3. **Curriculum**: easy target (centered, medium) → hard target (극단적 앵글) 순서 학습

### 학습 방법 개선점

1. **학습 데이터 부족**: 5k 이미지에서 17,600 pairs → 2B 모델 fine-tuning치고 매우 적음
   - max_pairs_per_image=32인데 유효 neighbor ~160개, 20%만 사용
   - 10k 전체 이미지 + max_pairs 증가 + threshold 확대 → 10배 이상 데이터 확보 가능

2. **1 epoch만 학습**: num_train_epochs=1로는 부족. 3~5 epoch 권장.

3. **Loss 설계**: cross-entropy on JSON text tokens → 수치 회귀에 부적합
   - "0.35" vs "0.36": score 차이 0.01인데 token sequence 완전 다름
   - 모델이 정확한 수치 예측보다 텍스트 패턴 모방 학습할 위험
   - 개선: auxiliary regression loss on parsed scores, 또는 score별 가중치 차별화

4. **image_j 미사용**: image_i + action → predict j scores (j 이미지 안 봄)
   - 3D 추론을 순수하게 "상상"으로 해야 함 → c2o 예측이 본질적으로 어려움
   - 대안: (image_i, image_j) pair를 보여주고 관계 학습 (pre-training or auxiliary)

5. **단일 scene**: Namaqualand만 학습 → 일반화 불가. best25.json 활용 multi-scene 학습 필요

6. **Pair sampling 랜덤**: 거리 균등 분포 + hard negative mining으로 개선 가능

### 장기 (아키텍처)
1. **규칙 기반 초기 positioning + VLM refinement**: 3D geometry 활용해서 대략적 포즈 계산 후 MPC 시작
2. **모델에 거리/각도 정보 추가 입력**: 현재 카메라-오브젝트 거리, 각도를 prompt에 포함
3. **더 큰 모델 (7B/9B)**: 3D 추론 능력 향상 기대
