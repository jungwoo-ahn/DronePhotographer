1. Data: 학습 데이터 재설계 (v1 → v2)

1-1. 문제: "사람 프레임 잘림"을 학습 signal로 못 잡음

기존 occupancy(bbox 면적/이미지 면적, mask 기반) 하나만으로는 "적당한 크기로 잘 보이는 상태"와 "너무 가까워서 잘린 상태"가 구분 불가. 둘 다 occupancy < target.

1-2. 해결책: body_in_frame_ratio 새 metric 도입

정의: clipped_projected_area / full_projected_area
사람의 3D bbox를 이미지 평면에 projection → 프레임 안쪽으로 잘라낸 면적 / 잘라내기 전 전체 면적.
  • 사람이 프레임에 완전히 들어가면 1.0
  • 절반 잘리면 0.5
  • 완전히 밖이면 0.0
  • 거리와 독립적 (멀리 있어도 잘리지 않으면 1.0)
3D body bbox→ camera projection→ frame clipping→ area ratio

2. Training: Score Head regression + v2

2-1. 문제: Cross-entropy on JSON tokens이 수치 회귀에 부적합

모델이 "0.35" vs "0.36"을 완전히 다른 token sequence로 보게 됨. 실제 score 차이는 0.01인데 loss는 동등. 정확한 수치 예측보다 텍스트 패턴 모방을 학습할 위험.

2-2. 해결책: Score Head auxiliary regression loss

  • model.score_head = Linear(2048 → 14) 추가
  • prompt 끝의 hidden state → 14개 float 직접 출력
  • total_loss = lm_loss + α · L1(score_head(h), gt_scores), α=0.5
  • ScoreRegressionTrainer (train.py) · gt_score_values field (collator.py)

3. Inference: vLLM + Safety guards + Lookahead

3-1. vLLM 통합 — 속도

기존 HuggingFace model.generate()로 720 candidates 스코어링 = 매우 느림 (50 step MPC × 720 candidate = 36k forward pass)
  • score_action_candidates_vllm() 함수 신설 (src/vlm_qwen25/mpc.py, +202 lines)
  • --use_vllm, --tensor_parallel_size 플래그
  • PagedAttention + continuous batching
  • Tokenizer 호환성 fix: TokenizersBackend → Qwen2TokenizerFast
결과: 720 candidates를 ~9초에 처리 (H200 1장). vLLM 설치로 transformers 5.5→4.57, torch 2.11→2.10 다운그레이드, flash-attn 제거 (vLLM 내장 flashinfer 사용).

3-2. Safety Guards — 3종 세트

① c2o spike detection
이전 step의 c2o 예측 값과 현재 best candidate의 c2o 예측 값을 비교 → fx/fy/fz 중 하나라도 0.5 이상 변하면 "spike"로 판정 → 가장 작은 이동의 candidate 선택.

--disable_spike_detection 플래그로 끄기 가능 (iter4에서 중요하게 쓰임).

② Margin 하한 필터
예측된 bbox_margin_top, bbox_margin_bottom이 0.03 미만인 candidate를 제외. 사람이 상하단에서 잘리는 것을 방지. 모든 candidate가 조건 미달 시 skip (fallback).
③ Adaptive step size
현재 카메라-오브젝트 거리에 비례해서 step 스케일링. 
step_scale = clamp(distance / 4.0, 0.3, 1.0)
# 4m+ → × 1.0 (0.2m)
# 2m  → × 0.5 (0.1m)
# 1.2m → × 0.3 (0.06m, 최소)

3-3. 2-step Lookahead MPC

Greedy 1-step MPC는 "이번 스텝은 좋아보이지만 다음 스텝에서 사람이 사라지는" 경로를 예방 못함.
720개 1st candidate→ Top-30 선정→ 각각 50개 follow-up→ 기하 합성→ 재랭킹
  • relative_translation_camera_local(): current → final 위치를 현재 카메라 로컬로 변환
  • target_orientation_forward_up_camera_local(): final orientation을 현재 카메라 로컬로
  • build_action_text(): 합성된 단일 action text 생성
  • 합성된 전체를 한 번에 vLLM으로 스코어링, obj = 0.5·(1-step err) + 0.5·(lookahead err)로 재랭킹
  • 계산량: 720 + ~1500 = ~2,220 model calls/step (vLLM으로 감당 가능)

6. 남은 문제 · 향후 방향

6-1. 여전히 남은 근본 문제

  • 카메라 drift (MPC greedy 특성): 매 step 아래로 약간 이동이 단기 error 감소 → 누적되어 target은 eye-level인데 low angle로 끝남
  • Overshooting: 수렴 후에도 step을 계속 진행하면 최적점을 지나쳐 악화 (iter9)
  • vLLM inference hang: 특정 이미지에서 model.generate()가 멈춤 (iter6 seed=42)
  • 어려운 target 수렴 불가: left hero 같이 현재 위치에서 큰 각도 전환 필요한 target은 safety guards로 catastrophic failure는 막지만 수렴 X
  • v3-body의 접근 능력 부족: body_in_frame_ratio weight가 다른 score들의 영향력을 희석시켜 "다가가기" 행동을 약하게 만듦

6-2. 단기 개선 (코드 수정만)

  • Coarse-to-fine 2-phase: 규칙 기반으로 대략 위치 먼저 잡기 (3D geometry 활용) → VLM MPC로 정밀 조정
  • 더 큰 step size 허용: translation_values에 0.4~0.5m 포함 (멀 때만)
  • Drift 방지: target fz=0이면 z축 이동에 penalty
  • Early stopping: error가 threshold 이하로 떨어지면 종료 — overshooting 방지
  • vLLM timeout: 특정 시간 내 generate 안되면 fallback
  • generate_target.py validation 강화: occupancy+aspect 조합, c2o orthogonality 체크

6-3. 중기 개선 (학습 재설계)

  • body_in_frame_ratio를 hard constraint로: target score가 아닌 필터로만 사용 → 접근 능력 보존
  • image_j 활용: 현재는 image_i + action → predict j scores (j 안 봄). (image_i, image_j) pair pre-training으로 3D 추론 능력 향상
  • Multi-scene 학습: best25.json 활용 — 현재 Namaqualand 단일 scene
  • Pair sampling 개선: 거리 균등 분포 + hard negative mining
  • Score Head weight α 조정: α=0.5이 너무 커서 LM loss 학습을 희석했을 가능성

6-4. 장기 (아키텍처)

  • 규칙 기반 초기 positioning + VLM refinement
  • 거리/각도 정보를 prompt에 명시적으로 입력
  • 더 큰 모델 (7B/9B)으로 3D 추론 능력 향상
  • Non-greedy planner: MPC 대신 A* / sampling-based planner로 long-horizon 최적화
