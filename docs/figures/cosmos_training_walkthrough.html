2 · Data flow — from data.json to Sample to batch tensor

A placement contributes ~24 × K_accepted training samples (24 windows per 32-frame trajectory at stride 1, times K_accepted = up to 12 trajectories). Across the 7,885 placements × K_mean = 10.67 from Stage 1, that's ~2.0M training samples. def encode_action_5d(prev_pos, prev_fwd, prev_up, next_pos, next_fwd, next_up):
    dt = relative_translation_camera_local(prev_pos, next_pos, prev_fwd, prev_up)
    rel = relative_rotation_matrix_camera_local(prev_fwd, prev_up, next_fwd, next_up)
    yaw, pitch = yaw_pitch_from_rotation_matrix(rel)        # roll is dropped
    return np.array([dt[0], dt[1], dt[2], yaw, pitch], dtype=np.float32)

value_target — geometric profile distance

# src/policy/common/reward.py
def geometric_profile_distance(achieved, goal, intr: CameraIntrinsics) -> float:
    a = profile_to_geometry(achieved, intr)   # → {az, el, size, aim_x, aim_y} radians
    g = profile_to_geometry(goal, intr)
    d_view = great_circle(a["az"], a["el"], g["az"], g["el"])    # cyclic-safe
    d_size = a["size"] - g["size"]                                  # atan(bbox_half / focal_px)
    d_aim  = hypot(a["aim_x"] - g["aim_x"], a["aim_y"] - g["aim_y"])
    return sqrt(d_view**2 + d_size**2 + d_aim**2)

def profile_distance_value(achieved, goal, intr) -> float:
    return -geometric_profile_distance(achieved, goal, intr)   # 0 at goal, <0 away
Why weight-free? All three components are angles (radians) in the same camera-subject geometry, so they're summed without per-key weights to tune. atan on the size/aim pixel quantities makes off-frame / huge-bbox values saturate gracefully at ±π/2 instead of blowing up. The metric is scale-invariant, matching the profile's scene-agnostic design.

4 · Prompt & conditioner — T5 anchor + zero-init prefix injection

Cosmos-Predict2.5 was pretrained to consume (B, 512, 1024) T5-11B cross-attention embeddings for a natural-language prompt. We never load T5 at train/inference; instead we build that exact tensor by combining a frozen anchor (one-time T5 encode of a fixed prompt) with a zero-initialized learnable prefix of K=4 goal tokens. At init the conditioner output equals the anchor exactly — the backbone starts as the pretrained T5-conditioned model. Gradient descent ramps a scalar gate up so the goal signal can eventually drive the action / value predictions.

Why anchor + prefix instead of "Linear(8) → 1024"?

optionat initbackbone sees
raw Linear(8 → 512·1024) random off-manifold — the frozen Cosmos backbone has never seen those activations
anchor + zero-init prefix exact anchor — same as a T5-encoded prompt in-distribution — the model starts as the pretrained T5-conditioned policy and adapts from there
Escalation path if the gate plateaus at a small value while loss stalls: switch to IP-Adapter-style decoupled cross-attention — add a parallel (K, V) projection in each cross-attn layer that attends to a separate stream of goal tokens, with the output projection zero-initialized. That requires touching the backbone's Attention blocks but gives the goal signal much more capacity to integrate at every layer.

5 · Latent assembly — from batch tensors to x0 ∈ (B, 16, T_total, H_lat, W_lat)

Source: CosmosWorldActionPolicy.build_training_latents

def build_training_latents(self, image_latent, action_chunk, value_target):
    # image_latent: (B, C, T_img, H, W) — from vae.encode(assemble_clip(state, next))
    b, c, t_img, h, w = image_latent.shape
    n_extra = 2                              # 1 action + 1 value
    x0 = torch.zeros(b, c, t_img + n_extra, h, w, dtype=..., device=...)

    x0[:, :, :t_img] = image_latent           # clean image latents

    a_idx = t_img
    x0[:, :, a_idx] = inject_action_chunk(x0[:, :, a_idx], action_chunk)

    v_idx = t_img + 1
    x0[:, :, v_idx] = inject_value(x0[:, :, v_idx], value_target)

    return x0                                # clean target for the diffusion process

6 · EDM loss — σ sampling, preconditioning, per-component split

(a) σ sampling per batch sample

# src/policy/cosmos/edm.py
def sample_sigma(batch_size, config: EDMConfig, *, device):
    log_sigma = torch.randn(batch_size, device=device) * config.p_std + config.p_mean  # N(-1.2, 1.2)
    sigma = log_sigma.exp()
    if config.use_balanced_two_heads:
        sigma = apply_balanced_two_heads(sigma,
                    high_sigma_ratio=0.25,    # 25% → log-uniform [200, 100000]
                    low_sigma_ratio=0.25)      # 25% → uniform [1e-5, 2.0]
    return sigma                              # shape (B,)

Each batch sample gets one σ — the whole latent sequence (image + action + value frames) is corrupted with the same noise level. The three components are not sampled independently. The balanced-two-heads pass replaces a random 25% of σ values with extreme highs and another independent 25% with extreme lows. Without it, the log-normal alone undersamples the σ extremes where the two EDM "denoiser heads" (ε-prediction at high σ, x0-prediction at low σ) need supervision.

(b) Add noise: x_t = x0 + σ · ε

epsilon = torch.randn_like(x0)                # same shape as x0: (B, 16, T_total, H, W)
sigma_v = sigma.view(B, 1, 1, 1, 1)            # broadcast across all dims
x_t = x0 + sigma_v * epsilon                   # noisy latent

(c) Backbone forward under EDM preconditioning

# Karras 2022 eq. 7: precondition the input and output so the network's effective
# task is well-conditioned regardless of σ.
c_skip = sigma_data² / (sigma² + sigma_data²)
c_out  = sigma · sigma_data / sqrt(sigma² + sigma_data²)
c_in   = 1 / sqrt(sigma² + sigma_data²)
c_noise = 0.25 · log(sigma)                       # scalar fed in as "timestep"

# Forward call (DiffusersStyleAdapter):
net_out = transformer(
    hidden_states=x_t * c_in,                    # scaled input
    timestep=c_noise,                             # σ-derived "timestep"
    encoder_hidden_states=cond.crossattn_emb,     # P*-injected anchor (B, 512, 1024)
    encoder_attention_mask=cond.padding_mask,
)

x0_pred = c_skip * x_t + c_out * net_out         # preconditioned x0 prediction

(d) Per-σ weighting + per-component split

# Karras 2022, EDM scaling — weight emphasizes losses at "useful" σ ranges.
w(σ) = (σ² + sigma_data²) / (σ · sigma_data)²

sq = (x0_pred - x0) ** 2 * w(σ).view(B, 1, 1, 1, 1)   # (B, C, T_total, H, W)

# Split by latent-sequence position so each component is on a comparable scale.
L_world  = sq[:, :, :T_img         ].mean()                  # pos 0..T_img-1
L_action = sq[:, :, T_img          ].mean()                  # pos T_img
L_value  = sq[:, :, T_img + 1      ].mean()                  # pos T_img + 1

total = λ_w · L_world + λ_a · L_action + λ_v · L_value       # λ = 1.0 / 1.0 / 1.0
return LossOutputs(total, L_world, L_action, L_value)
The three components are not three separate forward passes. The backbone sees the whole noisy sequence at once and produces one denoised tensor; we just slice that tensor by latent-frame position when computing the loss. Goal conditioning enters at every layer of the trunk via cross-attention.

7 · Training loop — CosmosPolicyTrainer.fit

The frozen-backbone shortcut

# model.py CosmosWorldActionPolicy.__init__
if freeze_backbone:                              # default True for prototype

        p.requires_grad_(False)

# trainer.py _build_optimizer
params = [p for p in self.policy.parameters() if p.requires_grad]
# = ShotProfileVectorConditioner.goal_proj.{weight, bias} + .gate
# ≈ 33K params (8·4·1024 + 4·1024 + 1)
# vs the 2B-param backbone that stays frozen
Why so few trainable parameters? The "Cosmos Policy" recipe is to keep the 2B-parameter backbone frozen and only train the goal conditioner. The whole policy adapts by learning what 4 prefix tokens to inject and how strongly (via the gate). This is similar to LoRA-style PEFT but simpler — no rank decomposition, just a Linear + gate. If results plateau, the next move is to unfreeze the backbone (or LoRA-adapt it), not to add more conditioner capacity.

8 · Inference — CosmosWorldActionPolicy.sample

@torch.no_grad()
def sample(self, image_latent, goal_vec, *, n_steps=32, denormalize=True):
    # image_latent: (B, 16, T_img, H_lat, W_lat) — clean conditioning frames
    # goal_vec:     (B, 8)                       — already normalized via normalize_goal()

    b, c, t_img, h, w = image_latent.shape
    t_total = t_img + 2                                       # + action + value
    cond = self.conditioner({"goal_vec": goal_vec})              # anchor + gate·goal_tokens

    sigmas = karras_sigma_schedule(n_steps, self.edm, device=...)   # (n_steps + 1,)
    x = torch.randn(b, c, t_total, h, w, device=...) * sigmas[0]    # start at σ_max
    x[:, :, :t_img] = image_latent                                  # PIN image frames

    for i in range(n_steps):
        sigma_i, sigma_next = sigmas[i], sigmas[i + 1]
        x0_pred = self._backbone_x0_pred(x, sigma_i.expand(b), cond)
        d = (x - x0_pred) / sigma_i.clamp_min(1e-8)
        x = x + (sigma_next - sigma_i) * d                          # Euler step
        x[:, :, :t_img] = image_latent                              # RE-PIN each step

    a_idx, v_idx = t_img, t_img + 1
    pred_action = extract_action_chunk(x[:, :, a_idx],              # split-tiles + mean
                       chunk_size=self.chunk_size, action_dim=5)
    if denormalize:
        pred_action = pred_action * self.action_scale               # buffer; ckpt-persisted

    pred_value = extract_value(x[:, :, v_idx])                      # spatial mean

    return PolicyOutputs(pred_latents=x,
                         pred_action_chunk=pred_action,
                         pred_value=pred_value)

Karras σ schedule

# edm.py karras_sigma_schedule(n_steps=32, ρ=7, σ_min=2e-3, σ_max=80)
# σ_i = (σ_max^(1/ρ) + i/N · (σ_min^(1/ρ) - σ_max^(1/ρ)))^ρ
# σ_{N} forced to 0 (clean target)
# At ρ=7, the schedule front-loads denoising into the high-σ end (Karras 2022 Algorithm 1).

Why pinning matters

The image-conditioning frames carry no noise — they're the input to the policy, not something we're sampling. By overwriting x[:, :, :T_img] with image_latent both at init and after every Euler step, the diffusion process effectively becomes a conditional sampler that denoises only the action and value slots. The trunk's self-attention can still mix information between image and action/value at every layer, so the image observation gets to inform the action prediction throughout sampling.

Action de-tokenization — tile reduction + mean

# action_latent.py extract_action_chunk
def extract_action_chunk(latent_frame, *, chunk_size, action_dim=5):
    b, c, h, w = latent_frame.shape
    n_latent = c * h * w
    n_action = chunk_size * action_dim
    n_repeats = n_latent // n_action

    flat = latent_frame.reshape(b, -1)
    repeats = flat[:, :n_repeats * n_action].reshape(b, n_repeats, n_action)
    chunks = repeats.reshape(b, n_repeats, chunk_size, action_dim)
    return chunks.mean(dim=1)                                   # average over all tile repeats
                                                            # → robust to per-element diffusion noise
Inference modes. With chunk_size=8 the policy returns 8 future actions per diffusion sample — we execute the first one (or all 8 open-loop) and re-roll. For best-of-N planning, draw N independent samples (different noise seeds → different x0_pred) and pick the chunk with the highest V̂. No MPC, no candidate-action sampling at the env, no lookahead beyond one diffusion call.
