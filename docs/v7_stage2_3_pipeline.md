# V7 Stage 2 + Stage 3 — Render / Score

Two-machine plan. **jungwooahn** renders + scores the lower half of the
placement list; **jooyeol** does the upper half. Both sides run identical
commands with `--side` swapped. Outputs land in disjoint placement
directories, so no cross-machine merge is needed.

GroundingDINO is **not** used. Subject bboxes come from projecting the
subject mesh (~5k vertices) through the camera at render time — same
projection helper the Stage 1 in-frame check uses. CPU-only scoring; no
detector dependencies on either machine.

## Settings (must match across both sides)

| | |
|---|---|
| Frames per pair | **32** (all of `trajectory_32f`) |
| Resolution | **1024 × 768** |
| Cycles samples | **32** |
| Format | **JPEG, quality 82** |
| Depth | not rendered |

The pilot may reveal that some setting needs to change (e.g. drop samples
to 16 if the wall-clock projection is too long). Whoever pilots edits
this memo and pings the other side before the full run.

## Split manifest

`splits/v7_stage2_assignments.json` (generated by
`scripts/v7_stage2_make_split.py`, committed to
`v7_data_for_cosmos_policy`). Schema:

```json
{
  "version": 1,
  "total_placements": 7885,
  "split_method": "sorted_by_(scene_file,placement_name)_then_halve",
  "sides": {
    "jungwooahn": {"count": 3942, "placements": [...]},
    "jooyeol":    {"count": 3943, "placements": [...]}
  }
}
```

Both sides write into `outputs/v7_stage2_renders/<placement>/…`.

## Per-placement output convention

```
outputs/v7_stage2_renders/<placement>/
    renders/pair_<pp>_frame_<ff>.jpg     # 32 frames × K_accepted pairs
    data.json                            # Stage 1 fields + render_records (bbox, occupancy) + per-frame scores
    done.flag                            # Stage 2 (render + bbox) complete
    scored.flag                          # Stage 3 (21 keys) complete
    failed.flag                          # any stage failed; contains traceback
    backfilled.flag                      # bbox was added post-hoc (only on older renders)
```

`render_records[pair_idx]` is a list of:
```jsonc
{
  "frame_idx": 15,
  "path_rel": "renders/pair_00_frame_15.jpg",
  "bbox_xyxy_full": [x1, y1, x2, y2],   // may extend off-image; null if subject behind cam
  "occupancy_clipped": 0.184,
  "in_frame": true,
  "scores": {                            // populated by Stage 3 — V5 schema (8 ints)
    "occupancy": 18,
    "body_in_frame_ratio": 95,
    "cam_to_obj_azimuth_deg": 243,
    "cam_to_obj_elevation_deg": -11,
    "object_center_x": 419,
    "object_center_y": 282,
    "bbox_x_offset": 117,
    "bbox_y_offset": 310
  }
}
```

## One-time setup on each machine

1. Pull the branch:
   ```bash
   git fetch origin
   git checkout v7_data_for_cosmos_policy
   git pull --ff-only
   ```

2. Symlink scene/object assets + Blender from the main DronePhotographer
   repo (gitignored, not in the v7 worktree):
   ```bash
   ROOT=/path/to/DronePhotographer-v7
   MAIN=/path/to/DronePhotographer
   ln -s "${MAIN}/blender"      "${ROOT}/blender"
   ln -s "${MAIN}/data/scenes"  "${ROOT}/data/scenes"
   ln -s "${MAIN}/data/objects" "${ROOT}/data/objects"
   ```
   Alternatively pass `--assets-root /path/to/DronePhotographer` to the
   render script.

**No GroundingDINO install required.** No torch/CUDA setup either —
Cycles uses Blender's bundled CUDA/OPTIX, and scoring is pure numpy.

## Step 1 — Pilot (50 placements, GPU 0)

```bash
# Stage 2: render + bbox
blender/blender -b -P scripts/v7_stage2_render.py -- \
    --stage1-dir outputs/v7_stage1_sample \
    --placements-v6-dir data/vlm_object_placing_v6_260428_061326 \
    --assets-root "$(pwd)" \
    --out-dir outputs/v7_stage2_renders_pilot \
    --assignment-file splits/v7_stage2_assignments.json \
    --side jungwooahn --pilot-count 50 \
    --frames-per-pair 32 --render-samples 32 --resolution 1024 768 \
    --gpu-index 0

# Stage 3: rule-based + v5 + camera-3D scoring (CPU, single process)
python3 scripts/v7_stage3_score.py \
    --out-dir outputs/v7_stage2_renders_pilot \
    --assignment-file splits/v7_stage2_assignments.json \
    --side jungwooahn --pilot-count 50
```

**Sanity check** (before scaling up):
- Spot-check 5 random placements visually. Subject in frame, scene scale OK.
- Open one `data.json`. Each `render_records[*][*]` has `bbox_xyxy_full`,
  `occupancy_clipped`, `in_frame`, and `scores` (21 keys).
- v2 elevation sanity: pick a frame where the camera looks down on the
  subject. `scores.cam_to_obj_elevation_deg` should be negative. If
  positive, rerun Stage 3 with `--elev-sign pos`.
- Extrapolate Stage 2 wall-clock from `stage2_time_render_s` for the full
  half. Target: ≤ 10 days on 7 × 3090.

## Step 2 — Full half-run

### Stage 2 (render + bbox; dominant cost)

```bash
GPU_DEVICES="0 1 2 3 4 5 6" \
ASSIGNMENT_FILE=splits/v7_stage2_assignments.json \
SIDE=jungwooahn \
FRAMES_PER_PAIR=32 RENDER_SAMPLES=32 RESOLUTION="1024 768" \
RESUME=1 \
bash scripts/v7_stage2_batch.sh
```

(`SIDE=jooyeol` on the other machine.)

Slice logs live at `outputs/v7_stage2_renders/_logs/slice_<i>.log`.

### Stage 3 (score; CPU, single process)

```bash
python3 scripts/v7_stage3_score.py \
    --out-dir outputs/v7_stage2_renders \
    --assignment-file splits/v7_stage2_assignments.json \
    --side jungwooahn --resume
```

Fast — dominated by JSON read/write, not score arithmetic.

## Backfill for already-rendered placements

If you previously rendered Stage 2 with an older version that didn't
capture bbox, run the backfill once. No re-render — just opens the scene
and projects the subject mesh against the stored camera poses.

```bash
blender/blender -b -P scripts/v7_stage2_backfill_bbox.py -- \
    --out-dir outputs/v7_stage2_renders \
    --assets-root "$(pwd)" \
    --assignment-file splits/v7_stage2_assignments.json --side jungwooahn
```

After backfill, `scored.flag` is absent, so the Stage 3 score command
above will pick them up.

## Resume semantics

| Stage | Flag checked (skip when present) | Flag written on success |
|---|---|---|
| 2 render | `done.flag` | `done.flag` (also bbox in `data.json`) |
| 2 backfill (existing renders only) | `backfilled.flag` | `backfilled.flag` |
| 3 score | `scored.flag` | `scored.flag` |

Mid-run kill + relaunch with `--resume` is safe.

## Failure handling

A placement that throws gets `failed.flag` (Stage 2) or
`score_failed.flag` (Stage 3) with the full traceback.

```bash
find outputs/v7_stage2_renders -name '*failed.flag' | while read f; do
  echo "=== $(dirname "$f") ==="
  head -20 "$f"
done | less
```

Delete the failure flag to retry on the next run.


## Score family (V5, 8 ints)

Each frame's `scores` dict has the **V5 integer schema** (8 keys) — the
same shape the Qwen VLM training target uses. Computed from bbox +
camera pose + object rotation via `src/scoring/bbox_control.py:compute_v5_scores`:

| Key | Range | Meaning |
|---|---|---|
| `occupancy` | 0..100 | % of image covered by clipped bbox |
| `body_in_frame_ratio` | 0..100 | % of full bbox area that is in-frame |
| `cam_to_obj_azimuth_deg` | 0..359 | cam→obj direction azimuth in object-local frame (v2) |
| `cam_to_obj_elevation_deg` | -90..+90 | cam→obj elevation; -90 = cam directly above subject |
| `object_center_x` | int (px) | x of full bbox center (may exceed W) |
| `object_center_y` | int (px) | y of full bbox center (may exceed H) |
| `bbox_x_offset` | int (px) | half-width of full bbox |
| `bbox_y_offset` | int (px) | half-height of full bbox |

Other score families (rule-based 7, camera-3D 6, subject-aware 8) are
intentionally not computed.
